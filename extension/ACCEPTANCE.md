# 0.2.0 验证记录

2026-10-17，在 macOS Chrome 的已登录 ChatGPT 网页验证。以下真实浏览器验证与本地模拟演示分开记录，不包含账号或会话地址。

## 真实 ChatGPT

| 操作 | 观察结果 |
| --- | --- |
| 主线先回答 Transformer 推理总览，包含 KV Cache 等术语 | 原生主线保留一轮问答 |
| 从 KV Cache 卡片询问缓存内容与加速原因，要求此支线记住“书签”类比 | 自动创建原生分支，问题由 ChatGPT 回答，回答回到原卡片 |
| 收起再展开，追问“继续用刚才约定的类比，解释为什么它会占用显存” | 同一卡片返回第二轮，继续使用“书签”类比；主线仍只有原来的一轮 |
| 在第一条支线回答中选中“Key 和 Value”，展开子支线，要求沿用父支线的类比 | 子卡片内返回“书签上的索引标签”和“书签指向的具体内容”，继承父支线起点的语境 |
| 收起术语支线，在主线原生输入框继续问训练与推理的区别 | 原生主线正常回答，主线变为两轮；支线问题没有追加到主线 |
| 重命名主线回答卡片 | 本地目录标题更新，ChatGPT 原文保留 |

调试中修复了新聊天分支子菜单、首次发送前的临时原生分支地址，以及富文本换行表示差异。已发送命令不会因轮询或页面重载自动重放。

## 自动化与构建

- 原生分支协调：连续追问复用同一上下文、父子来源、临时地址转为真实会话地址、重启不重发、并行请求保护、清空/恢复任务隔离。
- 实际 React 卡片：展开、发送、回答显示、收起/重开、子卡片、目录定位，且原生回答 HTML、来源链接、主线输入框身份和值保留。
- 导入与备份：树关系、草稿、折叠状态和上下文地址往返；过滤跨源地址、孤立节点与循环。
- 执行最终生产 content script 和 service worker，检查无 Node 全局对象时启动、新旧 ChatGPT DOM、行内卡片和关闭侧栏后的折叠交互。
- `pnpm test`、`pnpm lint`、`pnpm build`、`pnpm extension:build`。

本地演示的回答明确标记为模拟数据，用于界面交互检查，不作为模型或原生上下文能力的证明。重启后的完整历史恢复主要由自动化验证覆盖，未完成独立的真实浏览器验收。

## 原型边界

复杂原生内容与 agent 确认继续在对应原生分支标签页操作。后台标签页节流、登录/确认窗口、历史虚拟化以及未来 ChatGPT DOM 变动仍可能需要打开原生页或更新适配器。此轮没有执行真实 agent 任务、附件上传或深度研究验收。
